# Fruit Merge

A drop-and-merge physics game (drop fruit, matching pairs merge one size up, 11 sizes, the last is a watermelon). Static site, no build step, no dependencies, installable as a PWA. Hosted from the repo root (GitHub Pages style).

Rogue mode is a full roguelite: charms, tools, fusions, seeds, crates, bosses with phases, awards, stakes and starting jars. All seven stages of the expansion plan below are done. Classic and Wild are finished and should not change unless asked.

## Run and test

- Run: `python3 -m http.server 8000` in the repo root, open `http://localhost:8000`. Opening the file directly also works, minus the service worker.
- No test suite. Verify changes by driving the page with Playwright (preinstalled in cloud sessions): load, start a Rogue run, drop fruit, open the shop, check the console for errors. Keep throwaway scripts out of the repo.
- Syntax check quickly by loading the page headless and failing on any `pageerror`.
- The engine can be stepped by hand in a test: `G.g.up(x)` drops, `G.g.update(.016)` advances one frame, so a whole jar plays in milliseconds. `G.g.peek()` returns the engine's hidden state (drops left, held fruit, armed tool, the bee), `G.g.snap()` the pile, `G.g.load(pile)` sets it. A drop is ignored while `cool>0` (the first 0.4s of a jar, 0.55s after each drop), so step between drops. Top-level `const`s (`G`, `RUN`, `RG`, `PF`) are reachable from `page.evaluate`.
- **Dev panel**: open the page with `?dev`. Jump to any depth and jar, set the boss, add charms (fusions included), tools, upgrades and seed levels, put a contract on offer, give a skip reward, open a crate of any tier, add coins, clear the jar being played, log or reset the profile, unlock everything. Any run it touches gets `R.dev=1`: no stats, no glossary marks, no score boards. Add new item types to it as they land.

## Code conventions

- Hand-written dense style: short names, many statements per line, one function per line where possible. Match it. Do not reformat existing lines, diffs must stay readable.
- No frameworks, no bundler, no npm. Plain script tags.
- UI screens are HTML strings passed to `show(html)`, which fills `#ui .msg`. Buttons carry `data-a="action"`, dispatched in one click listener (`rgAct` for Rogue actions, all prefixed `r`).
- Icons: `ic('name')` returns `<i class="px px-name">`. `fr0` to `fr10` are pictures of the fruit sizes, drawn at load from `drawFruit` (seeds use them). A charm, boss or upgrade uses the grid named after its id unless `ICN` maps it to another. Every new item needs a grid in `icons.js` or an `ICN` entry.
- What's new: `LOG` in `index.html` (newest first, `news()` shows it from the menu, which marks it New until opened). Add a short player-facing entry for every change players will notice, and bump the version.
- Canvas text goes through `T()`, score pop-ups through `dmg()`, plain floating text through `floatTxt()`.
- Charm animations: `rgPulse(ids)` plays the charm's entry in `ANIM` (a CSS move `m-<name>` on the header icon, plus particles from `slotFx`). In the jar, `jfx(ids, merge)` in `makeGame` plays spot effects using `ring()` and `spray()`. Every new charm needs an `ANIM` entry.
- Sounds are synthesised in `SFX`, played with `snd('name')`.
- Font is Jersey 15, embedded as base64 in `index.html`. Do not open that line in an editor view if avoidable, it is huge.
- In-game text is short, plain and literal. A description must say exactly what the item does, with numbers.

## Architecture

- `store`: localStorage wrapper, keys prefixed `fruitMerge.v1.`. Keys in use: `mode`, `name`, `vol` (volume 0 to 1, v1.32.4, 0 is muted: `VOL`, `setVol`, the control `volB()` in Options and on the pause screen, `volUi()` updates it in place; `snd2` was the old on/off flag and is only read once to seed `vol`), `scores2`, `scoresWild2`, `scoresRogue`, `run` (the saved Rogue run), `profile` (all meta progress), `jar` and `stake` (the last picks on the new-run screen, a device preference), `seenLog` (newest What's new version opened), `art` (pixel fruit art, default on; off = drawn fruit, from the Options screen `opts()`), `tz` (text size, v1.32.3: 0.85, 1 or 1.15, a device preference. `tzSet()` writes it to the CSS variable `--tz`, which is the `zoom` of `.msg` and `.tip`. The panel's `max-width` is divided by it so the panel keeps its width, and `tipShow` divides the card's own lengths by `TZ`. Menu sizes are fixed CSS px, so a phone with a narrower CSS viewport, about 360 against 412 to 450, shows the same menu bigger and fits less), `title` (the title worn, a device preference), `look` (the looks worn, `{jk,bg,fs,ss}`, a device preference), `auth` (the signed-in account: uid, email, name, tokens).
- `G`: app state. `G.state` is one of `menu`, `play`, `pause`, `over`, `rogue` (any Rogue screen between jars). `G.g` is the live game, `RUN` the live Rogue run.
- `makeGame(W,H,wild,onOver,ro)`: the engine (physics, merging, specials, powers, drawing). Returns `{update, draw, up, use, jar, wipe, snap, load, scrub, ...}`. `ro` is null in Classic and Wild. In Rogue it is the hook object from `RG.ro(R, clear, fail, fx)`, the only way the engine talks to run state.
- `RG` (`rogue.js`): pure Rogue rules over a run object `R`: `new`, `saved`, `jarCfg`, `score`, `made`, `kill`, `payout`, `advance`, `stock`, `buy`, `sell`, `reroll`, and for tools `tool`, `ts` (slots), `need`, `charge`, `fill`, `buyTl`, `sellTl`. Read limits and prices through the helpers, never the raw tables: `slots` (charm slots), `ts`, `need` (charge a tool needs), `sellV`, `rrCost`, `upCost`, `upOk`, `sdCost`. Upgrades change all of them.
- Tools in the engine: `use(id)` fires a tool or arms a targeted one (`TL[id].tg`), `up(x,y)` then picks the fruit under the tap. `okTg(id,f)` says what a tool may target, `tool(id,f)` does the effect and returns false when there is nothing to do (no charge is spent), `spent(t)` empties the charge and runs every on-use charm. `power(p)` holds the four physics effects shared with Wild. Wild still uses coin prices and cooldowns (`PRICE`, `COOL`), Rogue never does.
- Tool bar: `#pw` holds Wild's four fixed buttons and `#tb`, the Rogue bar. The class `rg` on `#pw` switches between them. `syncTb` builds one button per slot and updates charge, Ready, Locked and armed states each frame.
- `PF` (`rogue.js`): the profile, one object under one storage key: `{v, rev, at, seen, unlocked, ach, stats, stakes}`. `seen`/`unlocked`/`ach` map namespaced ids (`ch.juicer`, `boss.fog`, `up.fert`) to the time first reached. `stats` is flat counters and records that only go up (`PF.inc`, `PF.max`). `PF.save()` writes only when dirty and is called from `rgSave`, `rgEnd`, tab hide and page hide. `mergeProfile(a,b)` joins two copies (earliest time, highest number) and is the whole sync story for sign-in. All meta progress must live in the profile.
- `rgEv(R, name, data)` (`rogue.js`): the single place things get counted, into `R.st` (run), `R.jst` (current jar, reset by the `start` event) and `PF.d.stats` (lifetime). The engine fires `drop`, `merge`, `tool`, `kill`, `net` through `ro.ev`. Screens fire `run`, `start`, `jar`, `end`, `buy`, `sell`, `up`, `seed`, `grow` (Gardener and Bloom), `roll`, `skip`, `crate`, `take`, `fuse`. `achCheck` runs at the end of it. New mechanics must fire an event here. The engine also fires `gold`, `melons` and `pet` (`k` = cat, mole or bee).
- `rgSee(kind, ids)`: marks things as met for the Almanac. Called when the shop, hub or a crate shows them. Kinds: `ch`, `tl`, `fu`, `up`, `sd`, `boss`.
- Awards (`ACH` in `rogue.js`, 76): the last 3 are for a Legendary (title Legend) and contracts, the 19 before them open looks (see Looks), the 17 before those are the hard ones (Bugtest, Fruit Fly, Pear-Shaped...), 14 of them give a title (`ti`), see `DESIGN.md`. They listen to engine events `exact`, `shave`, `overln` (pile went over the line this jar), `overf` (`l` = the fruit over the line at game over), `rainbow`, `rocks6`, `fly` (a fruit 2.5s without touching anything, `f.air`/`f.tc`), `ladder` (`lad` = sizes made in the current combo), `petr` (`l`), `mould`, plus screen event `leave`, `rt` on `drop` (right half) and `gold` on `merge`. Before those, the 8 newest cover the newer content (pets eaten, bees, 3 pets held, 6 gold merges, small fruit, 15 seed levels, The Blackout, a Trick Shot) and lock Big Appetite and 5 fusions. `on` = the events that can earn it, `t(R, d, S)` = the test, `un` = the lock key it opens (`ch.id`, `tl.id`, `up.id`, `fu.id`, `jar.id`, and for looks `jk.id`, `bg.id`, `fs.id`, `ss.id`), `secret` hides the text until earned. `LOCK` maps each key back to its award. `PF.lk(key)` is true while a thing is locked, and `RG.stock`, `RG.crate`, `RG.fusable` and `RG.upOk` all respect it. Earned awards go to `PF.d.ach` and `PF.d.unlocked`, to `R.got` (run over screen) and to `ACHQ` (the toast, shown by `toastTick`). Tests that need locked content must unlock it first: `for(const k in LOCK)PF.d.unlocked[k]=1`.
- Looks (v1.27, cosmetic only): `COS` in `rogue.js` holds 8 jar skins (`jk`), 7 backgrounds (`bg`), 3 fruit skins (`fs`) and 3 sound sets (`ss`), each opened by an award. `LOOK` (store key `look`) is what is worn, `lookSync()` resolves it into `LK` (the worn entry per kind, undefined = default) and must be called whenever the profile or `LOOK` changes. `drawBg` and `drawJar` draw the backdrop and the jar in every mode, `skinBuild` recolours the sprites through the skin's ramp (`FSK`, and `FSC` for the drawn fruit), `SFX.merge` reads `LK.ss`. The six looks from the hardest awards carry `a:1` and are animated (v1.30): Melon Rind, Crystal (`k:'prism'`) and Golden in `drawJar` (`per`/`star` place glints along the frame), The Deep and Sunset in `drawBg`, Black and White through `skinFx` (old film scratches over the jar). `RMO` (reduced motion) freezes every look. `cosIcons()` draws a preview of each as `px-cos_<kind>_<id>`. `looks()` is the picker (Options), `cosRow`/`cosList` are shared with the Almanac's Looks tab. An unlocked look's row names the award that earned it, what that award asks and the date (v1.30.1). Look awards that read lifetime stats also listen to `run`, so they count what was done before they existed. `PF.heal` opens the unlock of an award that was earned before it had one (Seasoned and Juiced gained jar skins). `alPct()` is the Almanac's completion (things met plus awards, the two `meta` awards left out), shown as a bar, and earned awards carry a dated stamp.
- Long screens (What's new, Run info, Almanac) have a sticky × at the top right (`.xb`) doing the same as their Back button.
- Almanac: `almanac(tab)` with `alRows(kind)` building the entries. Locked entries show the award's text, unmet ones a silhouette, met ones the full text and lifetime stats. Opened from the menu, the Rogue intro, the pause screen, and the shop and hub (`G.alFrom` says where Back goes). The Fruit tab lists the 11 sizes in order and the rock, always open (rows with `open:1` skip the met and locked checks). The rock icon is `fr11`, drawn by `drawStone` in `frIcons`.
- Rogue UI: `rgIntro`, `rgSetup` (pick jar and stake), `rgStart`, `rgHub`, `rgGo`, `rgClear`, `rgCrate`, `rgShop`, `rgInfo`, `rgCharm`, `rgTool`, `rgEnd`, `jarSum` (the Jar cleared summary: score, target, drops left, then this jar's stats from `R.jst`, where the merge event also keeps `bm` best merge and `bc` best combo), shared pieces `rgOwn` (owned charms and tools as tiles), `rgFuNote`, `rgSkipB`, header charm slots in `rgHead`, charm flash in `rgPulse`. Tapping an owned charm or tool (header slot or `rgOwn` tile) opens a small card next to it (`tipOpen`/`tipClose`, Balatro style) with Sell and, between jars, ◀ ▶ to reorder charms. Tapping anywhere else closes it. From the header in play it freezes the jar (`G.tipP`), and the closing tap never drops a fruit. `rgCharm`/`rgTool` (full-screen) are no longer reached from taps. In play the header has an i button next to pause (`#infoB`, shown by `syncInfo` from the loop): it and a tap on an empty part of the header open Run info through `infoGo`, which sets `G.inf` so that closing Run info (or selling from it) returns to the jar, not to the pause screen. `pauseMsg` and `resume` clear it. With slots full, the shop's buy button becomes Swap (`rswap`): a card (`tipShow`) lists owned items with their sell value, and picking one sells it and buys the new item into its place (`rswp2`). Tools have an optional short tool-bar name `s`.
- Titles: `titles()` lists the earned ones, `curTitle()` the one worn (Options picker, action `ttl`). Score boards show it before the name (`.ttl`), local scores and world scores store it as `ti`. Personal titles (`PTL`): a title for one account, keyed by its Firebase user id with the username it must sit beside and a look class (Habibti, `.ttl.hb`: pink glow, shimmer, rising pink pixels). `myT()` adds it to that account's `titles()` and it is worn on first sign-in if no title is set. `ttlH(ti, name)` builds every title tag and drops a personal title from a row with any other name. Never put an email in `PTL`, the file is public.
- Fruit names: `FN` in `rogue.js` (since v1.31 size 4 is the Lemon, was Mandarin; size 11 is the Watermelon, and must stay so: it was renamed Watermelon Queen by mistake in v1.31 and put back in v1.32.2), `fnm(l)` gives "Orange (5)", `fna(l)` adds a/an. A single size is named, ranges stay numeric.
- Accounts: optional, Firebase Auth email/password over REST (`authReq`, `authSet`, `idTok` refreshes the token, `authOut`), key `FB_KEY`. `users/$uid` holds `name`, `p` (profile JSON), `r` (run JSON), `sc` (local scores JSON), `ti`, `t`. `usernames/$lowercase` = uid, claimed with a multi-path PATCH (`claimName`). `cloudPull` on sign in merges the cloud profile with `mergeProfile`, joins scores (`scMerge`), takes the cloud run only if this device has none, then pushes. `cloudPush` (3s debounce, `1` = now) runs from `rgSave`, `rgEnd`, `saveScore`, the title picker and tab hide. Signed-in players skip the game-over name form and post as their username with `?auth=`. UI: the Account part of Options (`accB`) and `acct(mode)` for `in`, `up`, `reset`, `name`. Usernames can not be changed yet.
- Name filter: `nameBad(s)` (lists base64 in `NF`: A anywhere, W whole words, R staff-sounding, OK allowlist), `nameClean` keeps letters, numbers, space, `-`, `_`. Used for usernames, the game-over name and `lbSubmit`. `database.rules.json` repeats the character rule and the worst slurs as a regex.
- Leaderboard: `lbTop`/`lbSubmit`, Firebase REST, no SDK. Modes `classic`, `wild`, `rogue`. A Rogue score above stake 1 carries `k` (the stake). `lbSubmit` sends it and the title `ti`, and if the write is refused (database rules older than the fields) falls back to fewer fields. Rogue boards (world and this device) are grouped by Ripeness, highest first, the best `RPT`=5 of each (`rpRows`, headers use `rpB` and colours `RPC` green to deep red). `scKeep` trims a list: Rogue keeps 5 per Ripeness, other modes the top `MAXS`. The world Rogue board fetches the top 500 by score and keeps each name's best per Ripeness.

### Run object (save version `RV`, now 10)

`{v, jarId, stake, depth, jar, coins, total, ch:[{id, v?}], tl:[{id, c}] (tools, `c` = charge held), up:{one count per `UPG` key}, sd:[11 seed levels, index = tier made], bs:[boss ids per depth], ms:{depth: mini boss id}, bq:{depth: [two rule ids] for The Orchard Queen}, bx:{depth: extra rule id for a final boss on stake 8}, off (charms switched off by The Thief, only non-zero mid-jar), shop:{ch,tl,up,sd,cr,rr} (`cr` = kind of the crate on sale), crate:{tier,then,kind,opts}|null, ct:{id,on,sd?}|null (the contract on offer for the jar up next, `on` = signed), sk:[skip reward ids]|null (a skip pick that is open), tg:{skip reward id: uses left}, pile:[snapshot], at:'hub'|'shop'|'crate'|'skip', won, cfg, st:{run stats}, jst:{jar stats}, got:[awards earned this run], dsk (jars skipped this depth), dev?}`. Saved between jars only, never mid-jar. Any change to this shape needs a version bump and either a migration or dropping old saves. `RG.saved()` is the only reader and drops any save whose `v` is not `RV`. It migrates v9 saves to v10 (adds `ct`, `sk`, `tg`), and fills any `up` key the save lacks with 0, so a new upgrade needs no version bump.

## Rogue mode as it stands

- 8 depths, 3 jars each, the third is a boss. Beat depth 8 to win, then optional endless depths (targets ×`RSCX`=2 per depth).
- Each jar: reach `quota` points within `drops` drops. Charms that fire every few drops or merges show a countdown badge on their header slot (`G.g.cnt()` from the engine, meals for Chrysalis from the charm, drawn by `syncCnt`), red when the next one fires. On a boss or mini boss jar a tappable boss icon sits under Next (`#bossB`, shown by `syncBoss` from the loop): it pauses and shows the rules (`bossMsg`). Bosses with a rhythm show what is coming in the HUD tag line (`bossIn`: Tax, Whirlpool, Wilt, Glutton, Sticky, Frozen, Rock). Under Mult the HUD shows the last merge as points × Mult = score (`lsc`). The HUD shows drops left as a thick dark bar that drains, with the number written in it ("18 drops"): teal, orange at 8, red and pulsing at 5, never green, so it does not read as the score bar. A warning shows at 5, 3 and 1. Overflow (pile above the line for 2.2s) or running dry ends the run. The pile carries between jars and is wiped at each new depth.
- Scoring per merge: `(tri(l) + flat points) × Mult`, where `tri(l)=(l+1)(l+2)/2` for the fruit made, `Mult = (1 + sum of add) × product of x`. Charm order does not matter. Seeds add to both the points and the add part for their own size. After that, one-off multipliers stack on the result: gold fruit (×2, or ×3 from Golden Hand), Double Down (×4), Cyclone (×2), pollen (×3, ×4 with Butterfly Garden), Ladybird (×2).
- Charms (`CH`, 69, 5 Legendary and 22 fusions): passive items, rarity 0 to 2, fusions are rarity 3, Legendary is rarity 4 (see Legendaries). Six are award rewards (Snake Eyes, Magpie, Ashes, Sweet Spot, Abacus, Full House). Twelve fill thin builds (see `DESIGN.md`): Small Fry, Pip Collector, Bite Size, Crumbs (small fruit, Crumbs reads `sm`, the jar's merges that made size 4 or less), Gardener, Seed Packet, Sprout (seeds), Gold Leaf, Prospector, Alchemy (gold fruit), Wallflower, Low Tide (position). Eight make the Pets build (see below). Two rares grow ×Mult over the run: Snowball (×0.1 per jar cleared with 5+ drops left, `RG.snow`) and Old Oak (×0.04 per size 7+ fruit, in `RG.made`); `live:'x'` shows their value as ×. 5 slots (`SLOTS`), 6 with Charm Pouch. Hooks `chip`, `add`, `x` receive context `c` (see the comment above `CH`). Charms with no hook are special-cased in `makeGame` or `RG`. `dev:1` marks a prototype: dev panel only, never in the shop, crates or Almanac. `req` (an id or a list) means the item is only offered while the run holds one of those charms (`RG.rq`, used for charms and tools). Slingshot and Trick Shot (throwing) are in the shop for testing, Trick Shot only once Slingshot is held: with Slingshot, the release speed of a drag (`flick()` in the pointer handlers, passed as `up(x,y,vx)`) throws the fruit sideways at 0.35 of the flick speed above 300·K px/s, capped at 450·K (halved after the first playtest). A thrown fruit that hits a wall before touching anything gets `wb`, and a merge on its first contact is a `trick`.
- Tools (`TL`, 20 plus 6 fusions): abilities tapped during a jar. A run starts with Swap and Shake in 2 slots (`TS0`), up to 4 (`TSLOTS`) through the Tool Belt upgrade. Each tool needs `ch` charge and gains 1 per merge. Charge carries between jars, a bought tool arrives full. No coin cost, no cooldown. Targeted tools (Ripen, Twin, Midas, Anchor, Lead Weight) arm first, then the player taps a fruit. Tool charms: Juggler, Spark Plug, Showman, Overdrive, Crowd Pleaser, Encore, Battery, Dynamo. The Padlock boss locks tools.
- Fruit states added by tools: `gold` (Midas, ×2 and 2 coins when it merges, saved in the pile; also from Gold Leaf, Prospector and Alchemy), `anch` (Anchor, stuck until the next jar starts), `hv` (Lead Weight, v1.32: `HVM`=8 times the mass in the collision response and `HVG`=1.5 times the gravity, drawn with a lead rim, gone when it merges or the next jar starts, not in the pile snapshot, needs a human playtest), `pet` (Petrify / Medusa: turned to stone, `safe` from overflow, crumbles when the next jar starts and is left out of the pile snapshot). Gargoyle makes every rock safe from overflow and gives +0.5 Mult per rock (`rk` in the score context). Shatter turns a rock back into fruit. From pets: `pol` (pollen multiplier) and `lb` (the Ladybird), both saved in the pile snapshot as items 7 and 8. Jar states: `free` (Free Sample drops), `dd` (Double Down), `stash` (the Next fruit Rewind pushed back).
- Fusions: an entry in `CH` or `TL` with `fu:[a,b]`. Charm fusions take two charms, tool fusions take a tool then a charm. Never sold, never a random crate pick. `RG.fusable(R)` lists the ones the run holds both halves of, `RG.fuse` makes one: it takes the first half's place, frees the other slot, and a charm fusion keeps the halves' grown value. Recipes: Four-Leaf Clover (Lucky Clover + Horseshoe), Golden Goose (Piggy Bank + Savings Account), Volcano (Fireworks + Compost), Headliner (Showman + Encore), Smoothie (Juicer + Honey Pot), Marathon (Early Bird + Photo Finish), Wildfire (Hot Streak + Chain Reaction), Melon Mania (Heavyweight + Melon Fever), The Mint (Scratch Card + Golden Touch), Sharpshooter (Bullseye + Lodestone), Cyclone (Whirl + Metronome), Sleight of Hand (Swap + Juggler), Golden Hand (Midas + Fat Wallet). For the thin builds: Feeding Frenzy (Small Fry + Pet Caterpillar), Greenhouse (Gardener + Abacus), Treasure Hunter (Prospector + Magpie), Still Water (Low Tide + Clean Plate), Climbing Ivy (Wallflower + High Wire), Bloom (Ripen + Sprout, tool: the first use each jar also gives the new size's seed 1 level, via `ro.seed`), Snack Pack (Bite Size + Hoarder), Seed Vault (Sprout + Seed Packet), Philosopher's Stone (Gold Leaf + Alchemy, its 1 in 2 ignores Horseshoe), Keepsake (Pip Collector + Vintage), Fine Mesh (Sieve + Pip Collector, tool), Medusa (Petrify + High Wire, tool: also petrifies every fruit touching the target). Pets: Butterfly Garden, Menagerie, Nectar (Busy Bee + Pet Treats: pets eat pollinated fruit first and the meal takes the pollen ×3). Recipes are not shown before the player holds both halves (the user removed combo hints on purpose). The hub and shop then say "Fusion ready".
- Pets: Pet Caterpillar, Busy Bee, Mole, Hedgehog, Ladybird, combos Pet Bowl, Pet Treats, Chrysalis, Big Appetite (need a pet: `CAT`, `EAT`, `PETS` lists in `rogue.js`), tool Whistle, fusions Feeding Frenzy, Butterfly Garden, Menagerie, Nectar. Pets leave pollinated fruit alone (`pf` filters their targets, the hedgehog falls back to one if nothing else is in reach), with Nectar they go for it first. In the engine: the caterpillar is `cat` (`updCat`, shared with Wild and The Glutton, a Rogue pet one walks and eats faster), the rest are `bee`, `mole`, `hog` in `updPets`/`drawPets`. The Hedgehog is the defensive pet: when the pile reaches the gold line (`ptop<hiY()`, at most every 3 drops, `hogD`) it climbs up and eats the highest fruit of size 6 or less (`hogTg`). A call that finds no target, or comes while the pet is out, waits (`catQ`, `beeQ`, `moleQ`). The bee's target gets a dashed yellow ring from the moment the bee appears. If the target merges or is eaten before the bee lands, it takes the nearest fruit to that spot (`b.tx`/`b.ty`), usually the one the merge made. `jml` counts meals per jar for Pet Bowl. Chrysalis keeps its meal count in the charm (`n`) through `ro.chrys`.
- Legendaries (v1.29, rarity 4, `RAR[4]`, tile and slot class `r4`, sound `legend` through `rareCue`): never in the shop (`RG.stock` only takes `r<3`), never a fallback pick. `RG.crate` rolls one in place of a charm pick with chance `CRL`=0.02 in a bought Charm Crate and `CRT.melon.lg`=0.05 in a melon crate, at most one per crate (the pick carries `lg:1`). Phoenix (an overflow clears the top half once every jar, engine flag `phx`, tried before Safety Net), Cornucopia (`horn`, a merge making an Orange (5) or bigger gives 1 drop back), Heirloom (`heir`, ×1.5 and ×0.2 more per jar cleared, grown in `RG.advance`, `x0` = where a growing × starts), Stowaway (`stow`, ×1.5 and takes no slot: `RG.slots` adds 1 while it is held and `RG.blocked` never blocks it), White Flag (`flag`, `RG.jarCfg` sets `p2` and `p2s` false, so no boss reaches phase 2, Ripeness 8 included). They are in the Charms tab of the Almanac after the rares and count for its completion. The dev panel's Legendary button opens a Charm Crate that holds one.
- Crates (`CRT`): pick 1 of 3 free (4 with Crowbar), or leave it for a few coins. A boss drops a gold crate, a melon crate every 4th depth. Those two offer a ready fusion as the first pick. Wooden crates come from skipping and from the shop (one crate of a single kind per visit, prices in `CRP`, shown at the top of the shop with its own colour: icons `crate_ch`, `crate_tl`, `crate_sd` are the wooden grid recoloured at the end of `PXD`). Picks are charms, tools, seed levels or coins. Higher tiers mean rarer charms and more seed levels. A pick is blocked while its slots are full, and the crate screen lets the player sell to make room. Opening a crate plays `crateFx` once per crate (`G.crA`): a 72x72 canvas drawn from the `crate_<tier>` icon grid and scaled up pixelated, drop, shake (`snd('crsh')`), burst (`snd('crpop')`, lid and planks in quarter turns, confetti in `CRFX` colours), then the pick list rows pop in (`.crin`). The pick list panel is hidden (`.crw`) until the animation ends (v1.30.2), so nothing shows behind the crate. Tap skips, reduced motion skips it, the rare sound waits for the reveal. `RG.crate` builds one, `RG.take` / `RG.leave` resolve it and move on to `crate.then` (shop or hub).
- Skip: jar 1 or 2 of a depth can be skipped from the hub or shop. No payout, no shop, then a pick of two rewards (`rgSkip`, `RG.skip`, `RG.skipTake`): the wooden crate, or one other from `SKR` that is not already held: Free Rolls (the next 3 paid rerolls are free, `RG.rrBase` is the price without it), Double Pay (next jar cleared), Bigger Haul (next gold or melon crate offers 2 more), Extra Drops (+6 in the next jar played). Held ones live in `R.tg` and are shown on the hub, the shop and Run info (`rgTags`).
- Contracts (`CT`, 11, v1.28): from depth 2, every jar that is not a boss or mini boss jar offers one (`RG.offer`, called from `RG.advance`, `RG.skip` and the dev panel jump). It is a handicap: a boss rule at phase 1 (`r`: lock, fog, mirror, clock, lid, sticky, prune, stone, only once that boss's `min` depth is reached), fewer drops (`dr`), a higher target (`q`) or a shorter overflow timer (`fz`). Signing is optional and can be undone until the jar starts (`rct`, the block from `rgCt` under the Next line on the hub and in the shop). `RG.jarCfg` applies a signed contract to the current jar only and sets `cfg.ct`. Clearing the jar pays coins (a payout row), a seed level (`R.ct.sd`) or a wooden crate (gold on the Crate Jar), and fires the `ct` event. All contracts are handicaps on purpose: a goal with no cost would be free coins and would move the balance curve.
- Bosses (`BOSS`, 30): `d` = rule, `d2` = what phase 2 adds, `min` = first depth it can appear, `q` = target multiplier, `fin` = final boss. A run draws 7 different bosses for depths 1 to 7 and one final (Melon Queen, Orchard Queen, Reaper) for depth 8; the Melon Queen was The Melon King until v1.32.1, renamed on the user's call (the new watermelon sprite is her), her id is still `melon`, her icon grid `king` and her award id `king`, and again every 8th depth in endless. Depth 4 (and 12, 20...) also has a **mini boss** on jar 2: a normal boss rule with no phase 2, 2 more coins and a wooden crate. Boss jars can not be skipped.
- Boss phases: on the boss jar (`cfg.p2`), reaching half the target calls `phase2()` in the engine. Every rule flag in `B` goes from 1 to 2 and the code reads the flag's value (`seq%(B.sticky>1?2:3)`). One-off hits (Padlock drains tools, Hourglass takes 2 drops, Melon Queen drops a rock into the lowest gap with 3s of grace, and that rock (`safe`) never counts for overflow; since v1.32 his watermelon at the start of the jar is `safe` too, because on a part-full jar it came to rest over the line and ended the run in 4.7s with no move to make) happen there. `cfg.rules` lists the flags a jar switches on: one for a normal boss, two for the Orchard Queen (`RG.rules`). Texts come from `RG.bossD(R, id, depth, two)`, never straight from `BOSS[id].d`, because the Queen's text depends on the run.
- Boss machinery in the engine: `bossTick(dt)` runs every frame (line position for Lid and Tide, wall position for Vise, the phase switch, Leech drain, Clock auto-drop). `sc()` wraps every score so the Auditor can cap Mult, `chg()` wraps every tool charge so the Miser can slow it, `mx()` flips the aim for the Mirror. The Blackout darkens the jar (`dk` light level, `dkT` seconds lit, `dkN` drops until the next light, `dkTick`), drawing only the held fruit and the one falling on top. The walls `L`/`Rw` and the line `line` are variables now, with `L0`/`R0`/`line0` as the resting values (the pile snapshot uses the resting ones). `RG.has` ignores the first `R.off` charms, which is how the Thief works.
- Upgrades (`UPG`, 29): `max` caps how many can be owned, `now` marks the instant ones (Scrub, Bribe, Spring Clean). Owned ones cost 2 more each time. `r:1` makes an upgrade Uncommon (v1.30.3, only Good Taste so far): `RG.stock` picks the 3 on the shelf with `RG.pickW` and the weights `UPW` (Uncommon 0.4), and the shop and Almanac show the chip. Stacking with no cap: Fertiliser, Hot Sauce, Watering Can, Trellis. Capped: Tool Belt, Charm Pouch, Bigger Shelf, Seed Bag, Catalogue (the shop offers 2 upgrades since v1.30.3, 3 with it), Loaded Dice, Good Taste, Haggler, Vault, Packed Lunch, Whetstone, Slow Fuse, Tambourine, Crowbar. Ten were added in v1.31 and five retuned in v1.31.1 after a bot pass (`DESIGN.md`, Upgrades measurement): Trellis (`trellis`, size 7+ merges +30 points, in `RG.score`), Spring Clean (`clean`, instant, `G.g.clean()` clears the top half like Safety Net, offered like Scrub), Signing Bonus (`sign`, +2 coins per cleared contract, a payout row), Back Road (`road`, a skip pays 3 coins, in `RG.skip`), Crate Key (`key`, the shop crate costs 2 less, `RG.crCost`), Thick Skin (`thick`, phase 2 at 60% then 70% of the target, `RG.p2at` and `p2T()` for the wording, not offered on Ripeness 8 or with White Flag), Gold Scales (`scales`, +1 coin per gold merge), Ledger (`ledger`, interest per 3 coins, `RG.intN`), Overtime (`ot`, unused drops pay up to 5), Raised Rim (`rim`, Uncommon, the line 5% of the jar higher, in `bossTick`). The engine reads them through `ro.up(id)`.
- Stakes (`STAKES`, 8), shown to players as **Ripeness** (the code, saves and the score field `k` still say stake): each adds one rule on top of the ones below: 2 jars pay 1 coin less, 3 targets ×1.25, 4 three fewer drops, 5 shop prices +1, 6 a mini boss on every depth from 5, 7 one charm slot fewer, 8 bosses start in phase 2 and the final boss brings a second boss rule. `RG.stakeMax(jar)` is one above the best stake won with that jar: every jar opens its own levels. Wins are stored per jar in `PF.d.stakes`. All of it is read from `R.stake` inside `RG.jarCfg`, `RG.cost`, `RG.slots`, `RG.mid` and `RG.rules`.
- Starting jars (`JARS`, 6): Classic, and five opened by awards. Piggy (12 coins, interest cap +2, jars pay 1 less), Deep (+4 drops, targets ×1.15), Charm (+1 charm slot, starts with Swap only, 1 tool slot fewer), Tool Kit (3 tools and 3 slots, 1 charm slot fewer), Crate (no charms in the shop, every cleared jar drops a wooden crate). Read from `R.jarId` in the same helpers.
- Seeds: `R.sd[l]` is the level for the fruit of tier `l` (1 to 10, shown as size `l+1`). Each level gives `sdP(l)=4+2l` points and `SDM=0.25` Mult when that fruit is made. Price `SDC=3` plus `SDS=2` per level held (v1.23: was 0.5 Mult and 1 per level, see `DESIGN.md`, Seeds measurement). The shop offers sizes 2 to 8 before depth 4, every size after.
- Economy: jar payout `RPAY`, unused drops bonus, interest 1 per 5 coins (cap 4), shop of 3 charms, 2 tools, 2 upgrades (3 with Catalogue), 2 seeds and 1 crate, reroll from 2 coins, sell for half price. Coins are spent in the shop only.
- Balance tables: `RQ` (depth 1 targets), `RSC` (target multiplier per depth), `RSCX`, `RDROPS`, `RPAY`, and `c`/`ch` on each tool. `RSC` was set from bot runs, not human play: a bot that aims every fruit at a matching one and buys nothing scores about 230 points per 24-drop jar at any depth. The same bot buying greedily (first charm it can afford, no thought for synergy, no targeted tools) wins about 1 run in 12 on this curve and usually dies between depths 3 and 6. Re-measure after any change to scoring power. The last measurement (with the Pets build) is in `DESIGN.md`, with a rebuilt bot that aims a little worse than the original (~190 a jar): greedy win rate matched between the old and the new item pool. None of those bots bought seeds. A 13 Nov measurement (`DESIGN.md`, Seeds measurement) found seeds far ahead of every other purchase: 0 wins in 200 for charms only, 25 in 200 for ×Mult charms plus seeds. Fixed in v1.23 (seeds, Smoothie, Marathon), `RSC` unchanged: the same policy now wins 13 in 400. A bot that judges balance must buy seeds.

## Design pillars for the Rogue expansion

Taken from what makes Balatro and Vampire Survivors work, applied to a physics merger:

1. **Legible score maths.** Points × Mult stays visible at all times. Every item says what it adds in numbers.
2. **Targets outrun linear builds.** Quotas grow faster than flat bonuses, so a winning run needs a multiplying engine.
3. **Scarcity forces identity.** Few slots, so each pick commits the run to a build (small-fruit swarm, big-fruit, combo, economy, destruction, tool spam).
4. **Known threats, chosen answers.** The boss is shown in advance. Bosses attack builds, the player prepares.
5. **Risk for reward.** Skipping a jar, holding coins for interest, playing near the line.
6. **Skill still matters.** It is a physics game. Items change what a good drop is, they never play the game for you.
7. **Meta progression is content, not power.** Unlocks add options and harder stakes. No permanent stat boosts that make old stakes trivial.
8. **Active play.** Clickable tools should fire often and visibly change the jar.

## Standing decisions

1. Charm order is irrelevant to scoring. The Thief is the one exception: it switches off the leftmost charms, which players can reorder between jars.
2. Charms from before the expansion are never locked.
